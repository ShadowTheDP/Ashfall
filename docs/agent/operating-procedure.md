# Project Operating Procedure

Adapted from the `Code-Project` workspace procedure for a single standalone
Godot project.

## Core Rule

One project, one source of truth: this folder. Do not pull in content from
other games or from the `Code-Project` workspace except as read-only reference.

## Standard Entry Flow

1. `README.md`
2. `AGENTS.md`
3. `MEMORY.md`
4. `docs/agent/current-state.md`
5. For gameplay work: `docs/design/combat-feel.md`
6. For new systems: `docs/design/pillars.md`
7. Only then inspect the target scripts.

## Change Discipline

- Prefer the smallest complete change (Ponytail), except for content schemas
  and feel experiments, where the three exceptions in `AGENTS.md` apply.
- When changing a combat number, record **why** in the commit message or in
  `docs/design/combat-feel.md`. Numbers without a reason get reverted by the
  next person.
- When changing a state machine, update or add a headless check in `tests/`.
- When changing enemy data, re-run `tests/soak.tscn`; it exercises all three
  enemy behaviours through victory.
- When changing the HUD or camera, re-run the capture scene and inspect the
  PNGs. Blind UI edits are not acceptable while visuals are procedural.

## Validation Matrix

| Change | Minimum validation |
|---|---|
| JSON data / damage formula | `tests/run_tests.gd` |
| Player attack / hurt / roll | `tests/combat_probe.tscn` |
| Enemy AI / waves / drops | `tests/soak.tscn` |
| HUD / camera / shaders | `tests/capture_scene.tscn` + inspect PNGs |
| Anything | `tools/check.ps1` |

## Handoff Rules

At the end of a meaningful phase:

1. Update `docs/agent/current-state.md` (objective, decisions, next steps).
2. Update `MEMORY.md` only for durable decisions, commands, risks, or
   verification results.
3. Append to `Changing Description.txt` when the work is worth preserving in
   project history.
4. Update `README.md` / `AGENTS.md` in the same task if structure or workflow
   changed.

## Protected / Generated Paths

- `.tools/` — local Godot binary.
- `.godot/` — import cache; delete only to force a clean import.
- `output/` — screenshots and builds.
- `assets/audio/*.wav` — generated by `tools/make_sfx.py`.

## Export Policy

- Builds go to `output/build/`, never to the project root.
- Keep `.exe` + `.pck` split during development; embed the PCK only for a
  release build.
- Do not commit export templates or builds.
